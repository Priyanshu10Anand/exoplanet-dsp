Detecting Kepler-10b from Raw Photometry

A complete, file-by-file report on the six-stage pipeline: from photons to planetary dimensions

1. Purpose and Big Picture

Problem. Kepler-10b blocks only about 160 parts per million (ppm, ≈0.016%) of its star's light when it transits. That dip is far smaller than the noise in any single measurement. The task is to extract this tiny, repeating signal and convert it into physical quantities: planet size, orbital distance and speed.

Solution. Six scripts in three phases:

Phase Files Goal
A. Signal conditioning 1, 2, 3 Acquire data; remove spacecraft artifacts, bad points, cosmic rays and slow stellar variability
B. Signal detection 4, 5 Find the hidden orbital period, then stack all transits to amplify the signal
C. Astrophysical translation 6 Convert period, depth and duration into radius ratio, distance and speed 
Raw flux → [1] PDCSAP flux → [2] clean flux → [3] flat baseline at 1.0
→ [4] period P → [5] folded, binned transit (δ, τ) → [6] Rp/R*, a, v

Each stage depends on the previous one. For example, step 4 only works well if step 3 has flattened the baseline.

2. Phase A: Signal Conditioning

File 1: 01_acquire_data.py (Data Ingestion)

Queries NASA's Mikulski Archive for Space Telescopes (MAST) via the lightkurve API and downloads Kepler-10's brightness-versus-time record (its "light curve"). 

search_q3 = lk.search_lightcurve("Kepler-10", mission="Kepler", quarter=3, exptime=1800)
lc = search_q3.download()
  • mission="Kepler": use the Kepler space telescope.
  • quarter=3: Kepler's observing was split into ~90-day quarters; Quarter 3 is one continuous block.
  • exptime=1800: Long Cadence, one exposure every 1,800 s (30 min), giving about 4,300 points over 90 days.

Why PDCSAP flux. Pre-search Data Conditioning Simple Aperture Photometry is NASA's corrected flux. Spacecraft suffer pointing jitter and thermal expansion as sunlight heats the chassis, making the star drift across the CCD pixels and creating false brightness changes. NASA applies Principal Component Analysis (PCA) using Cotrending Basis Vectors (CBVs), the movement patterns common to all stars on the camera. Being common to every star, they must be instrumental, so they are subtracted from this star's signal.

File 1, in more depth

  • What lightkurve returns. download() gives a light-curve object with four key columns: time, flux, flux_err (per-point uncertainty) and quality (the 32-bit flag integer used in File 2). Kepler time is stored as BKJD, i.e. Barycentric Julian Date minus 2,454,833, so values near 170–260 correspond to Quarter 3 (late 2009).
  • Long vs short cadence. Kepler also offers Short Cadence (60 s). Long Cadence (30 min) is chosen because it exists for essentially the entire mission and has plenty of resolution for a 1.6 h transit (about 3 points per transit).
  • SAP vs PDCSAP. SAP is the summed pixel brightness inside a fixed aperture and still contains drift, focus changes and aperture losses. PDCSAP removes these and also corrects for light from neighbouring stars (crowding) and the fraction of the star's light falling outside the aperture, so transit depths are physically meaningful. Using SAP would put instrumental trends into every later step.
  • Default masking. lightkurve already applies a default quality bitmask on download, which drops the worst cadences. File 2 enforces the stricter quality == 0 rule.

File 2: 02_clean_and_mask.py (Robust Statistics & Quality Masking)

Removes missing data (NaNs) and flagged cadences, then destroys cosmic-ray spikes (high-energy particles striking the detector).

Quality flags.

clean = clean[clean.quality == 0]

Each point carries a 32-bit binary integer; each bit flags a problem (bit 3: reaction wheel desaturation; bit 17: cosmic ray detected). A value of 0 means every flag is clear, so any flagged cadence is discarded.

MAD-based sigma.

mad = np.nanmedian(np.abs(flux - median_flux))
sigma_mad = 1.4826 * mad
\[\sigma=\sqrt{\frac{\sum_{i=1}^{N}\left(x_i-\mu\right)^2}{N}}\]

The ordinary standard deviation squares each deviation, so one huge spike inflates σ, loosens the filter, and lets the outliers survive. The Median Absolute Deviation (MAD) is the median of absolute deviations from the median and barely reacts to extreme values. Multiplying by 1.4826 (≈ 1/0.6745) rescales MAD to equal σ for Gaussian data, giving an outlier-immune "one sigma".

Worked example. Take seven flux values: 10, 11, 9, 10, 12, 10, 500 (the last is a cosmic ray).
• Standard deviation: mean = 80.3, population σ ≈ 171. A +4σ cut sits at about 10 + 4×171 = 694, so the 500 spike survives.
• MAD: median = 10; absolute deviations are 0, 1, 1, 0, 1, 2, 490; their median is 1. So σMAD = 1.4826×1 ≈ 1.48, and the +4σ cut sits at about 10 + 4×1.48 = 15.9, so the spike is removed.
One bad point changed ordinary σ by a factor of ~100 but changed MAD not at all.

Why the median as the centre. The median is also outlier-resistant (a spike cannot drag it), so the clip window stays centred on the true typical flux.

Asymmetric clipping.

mask = (flux <= med + 4.0*sigma) & (flux >= med - 8.0*sigma)
Side Limit Reason
Upper +4σ Cosmic rays cause artificial brightening spikes; clip tightly
Lower −8σ A transit is a negative dip; a wide lower bound protects it

Symmetric ±4σ clipping could chop off the very planet we are searching for.

File 3: 03_detrend_baseline.py (Savitzky-Golay Pre-Whitening)

Stars pulsate, rotate and carry magnetic starspots, producing a slow wavy baseline known as 1/f colored noise (far more power at slow timescales). It dwarfs the planet signal and must be flattened to exactly 1.0 so the matched filter in step 4 works. 

flat_lc = clean_lc.flatten(window_length=151, polyorder=2)

How the Savitzky-Golay filter works: a 151-point window slides along the series; inside it a 2nd-degree polynomial (y = ax² + bx + c) is fitted by linear least squares, and its value at the window centre is the trend estimate.

Window size logic: 151 cadences × 30 min ≈ 75.5 h ≈ 3.1 days, while the transit lasts only ≈ 1.6 hours. The polynomial acts like a stiff board over a small pothole: it follows the slow 3-day stellar wave but ignores the 1-hour dip. Too short a window would follow (and erase) the transit; too long would miss real stellar variation.

Pre-whitening by division:

\[F_{\mathrm{flat}}(t)=\frac{F_{\mathrm{raw}}(t)}{F_{\mathrm{trend}}(t)}\]

The result is a flat line at 1.0 with transits pointing downward (e.g. 0.99984 for a 160 ppm dip).

Window length trade-off

Window (cadences) Duration Effect
5 2.5 h About as wide as the transit; the polynomial follows the dip and erases the planet
151 3.1 d ≈45× longer than the transit; follows stellar wobble, ignores the dip. Chosen
1001 20.8 d Too stiff; cannot follow starspot rotation, so slow trends remain and pollute the period search

A 2nd-order polynomial is chosen because it can follow one hill or valley (curvature) in the window while staying too smooth to bend into a 1.6 h dip. Because it is fitted by least squares over 151 points, white noise in individual points is averaged away and only the slow component is kept as "trend".

Practical note: lightkurve's flatten needs an odd window length, hence 151 rather than 150.

3. Phase B: Signal Detection

File 4: 04_bls_matched_filter.py (Box Least Squares Period Search)

The orbital period is unknown, so we search for it.

bls = BoxLeastSquares(time, flux)
periodogram = bls.power(periods, durations)
best_period = periodogram.period[np.argmax(periodogram.power)]

Why not an FFT? An FFT decomposes signals into sine waves, but a transit train is a periodic square pulse with a duty cycle of only ≈8% (1.6 h of a 20.1 h orbit). Representing such a narrow, sharp-edged pulse takes dozens to hundreds of harmonics, each holding a sliver of the power against its own noise, which wrecks the signal-to-noise ratio (SNR).

How BLS works (matched filtering):

  1. Choose trial periods P and trial durations τ.
  2. For each pair (and phase offset) build a synthetic periodic boxcar.
  3. Compute the signal residue: how well the data's dips line up with the boxcar.
  4. Plot score against period (the periodogram) and take the highest peak.

For Kepler-10 the peak is at P ≈ 0.837 days (≈ 20.1 h). The source calls this "mathematically guaranteed"; more precisely, it is the period that best fits a periodic box-shaped dip, which at this SNR is the planet's period. Aliases (P/2, 2P) can create secondary peaks, so the top peak should be sanity-checked.

BLS internals and sanity checks

  • Per-trial statistic. For each trial (P, τ, phase), the algorithm splits points into in-box and out-of-box groups. The fitted depth is δ = mean(out) − mean(in), and the detection strength grows with depth and with the number of in-box points: SNR ≈ (δ/σ)·√Nin. The "power" is a normalised version of this fit-quality score.
  • Period grid. Trial periods cannot be spaced arbitrarily. If P is off by ΔP, the box drifts by ΔP per orbit and by ≈ΔP·(T/P) over the whole baseline T. To keep drift under one duration, ΔP ≲ P·τ/T ≈ 0.837×0.067/90 ≈ 6×10⁻⁴ d. That is why thousands of trial periods are scanned.
  • Aliases. At P/2 the boxes fall on every transit but also on empty half-orbits, diluting the score. At 2P only half the transits are covered. Both score lower than the true P, so the true period usually wins at high SNR.
  • Illustrative SNR. If the point-to-point scatter were 100 ppm and ≈320 in-transit points existed, SNR ≈ (160/100)·√320 ≈ 29, a very strong detection.

File 5: 05_phase_fold_stack.py (Coherent Stacking & SNR Amplification)

One transit is ≈160 ppm deep, nearly invisible in the noise. Using the found period we stack all transits: 90 d ÷ 0.837 d ≈ 107 transits. 

folded_lc = flat_lc.fold(period=period, epoch_time=t0)
binned_lc = folded_lc.bin(time_bin_size=10_minutes)

Phase wrapping. Linear time t becomes orbital phase φ from −0.5 to +0.5, with 0 at mid-transit:

\[\phi=\left(\frac{t-t_0}{P}+0.5\right)\bmod 1\;-\;0.5\]

t₀ is a reference mid-transit time; (t − t₀)/P counts orbits, and mod 1 keeps the position within the current orbit. Every transit then lands at φ ≈ 0.

Binning (SNR boost). Points are grouped in 10-minute phase bins and averaged. By the Central Limit Theorem, independent white noise averages down:

\[\sigma_{\mathrm{binned}}=\frac{\sigma_{\mathrm{raw}}}{\sqrt{N}}\]

The signal is identical every orbit, so it does not average away: noise shrinks while the signal keeps full depth. This is called coherent because the repeating signal adds as N, while noise adds only as √N. (My estimate, not from the source: with roughly 30–40 points per bin, noise drops about 5–6×.) The clean, U-shaped transit then emerges, yielding depth δ ≈ 160 ppm and duration τ ≈ 1.6 h.

Worked noise arithmetic (illustrative). Transit lasts 1.6 h = 96 min, so about 3 long-cadence points fall in each transit. Over ~107 orbits that gives ≈320 in-transit points. Spread across ~10 ten-minute bins, that is N ≈ 32 points per bin. With an assumed per-point scatter of 100 ppm: σbinned = 100/√32 ≈ 17.7 ppm. A 160 ppm dip is then ≈ 9× the noise in each bin, versus only 1.6× in a single raw point.
Long-cadence points from different orbits fall at different phases (because P is not an exact multiple of 30 min), which is what lets 10-minute bins be filled even though each raw point is 30 min long.

The fold needs an accurate P. If P were wrong by even 6×10⁻⁴ d, the transits would smear across phase over 90 days and the stacked dip would be blurred and shallower. That is why File 5 depends on File 4.

4. Phase C: Astrophysical Translation

File 6: 06_physical_metrics.py

Inputs: period P, depth δ, duration τ, plus the star's mass and radius, which come from catalogs, not from this pipeline.

6.1 Planet size

rp_over_rs = np.sqrt(depth)
\[\delta=\frac{\pi R_p^{2}}{\pi R_\ast^{2}}=\left(\frac{R_p}{R_\ast}\right)^{2}\;\Longrightarrow\;R_p=R_\ast\sqrt{\delta}\]

The planet blocks light in proportion to its disk area relative to the star's; π cancels. This ignores limb darkening, so it is first-order. Example: √(1.6×10⁻⁴) ≈ 0.0126; with R* ≈ 1.07 R☉, Rp ≈ 1.5 Earth radii.

6.2 Distance from the star (semi-major axis)

a_cubed = (const.G * m_star_kg * period_seconds**2) / (4 * np.pi**2)
a_semi_major = a_cubed**(1/3)

Set gravity equal to centripetal force for a circular orbit:

\[\frac{G M_\ast m}{a^{2}}=\frac{m v^{2}}{a}\;\Rightarrow\;v^{2}=\frac{G M_\ast}{a}\;\xrightarrow{\;v=2\pi a/P\;}\;a^{3}=\frac{G M_\ast P^{2}}{4\pi^{2}}\]

This is Kepler's Third Law (a³ ∝ P²); the planet's mass cancels. Use seconds and kilograms; 1 AU ≈ 1.496×10¹¹ m. Example (M* ≈ 0.91 M☉, P = 72,300 s): a ≈ 2.5×10⁹ m ≈ 0.017 AU, about 23× closer than Mercury.

6.3 Orbital speed

v_orbit = (2 * np.pi * a_semi_major) / period_seconds
\[v=\frac{2\pi a}{P}\]

Distance (one circumference) over time (one period). Example: ≈ 2.2×10⁵ m/s ≈ 219 km/s, about 7× Earth's orbital speed.

The duration τ is listed as an input but these three formulas use only depth and period. τ can further constrain orbital geometry (impact parameter, inclination) and acts as a consistency check.

Assumed inputs (illustrative, literature-style): P = 0.837 d, δ = 160 ppm, M* = 0.91 M☉, R* = 1.07 R☉, with G = 6.674×10⁻¹¹ m³ kg⁻¹ s⁻², M☉ = 1.989×10³⁰ kg, R☉ = 6.957×10⁸ m, R⊕ = 6.371×10⁶ m.

The measured ≈1.6 h is a little shorter, which is consistent with a transit that crosses slightly off-centre (impact parameter b ≈ 0.5, using τ ≈ τcentral·√(1 − b²)). This shows how the duration constrains geometry, as noted above.

Frequently Confused Points

Why is the period found before the depth is "known"?
BLS estimates a rough depth and duration while searching; File 5 then refines them on the stacked, noise-reduced curve.
Does flattening remove the transit?
Not if the window is long compared to the transit (151 cadences vs ≈3). That ratio is the entire design rule of File 3.
Why not fold before flattening?
Folding needs P, and finding P needs a flat baseline. Slow stellar trends would otherwise dominate the BLS score.
Why does depth give size but not mass?
Transit photometry measures blocked area only. Mass requires radial-velocity data, which this pipeline does not use.
Is the result a measurement or an assumption?
P, δ and τ are measured from the data. a and v additionally rely on M*, and Rp on R*, which are external catalog values.

6. Glossary

Cadence
One measurement time step (30 min here).
Flux
Measured brightness of the star.
Transit
A planet crossing its star's disk, causing a small dip.
PDCSAP / CBV
Instrument-corrected Kepler flux / common instrumental trend patterns.
MAD
Median Absolute Deviation, an outlier-resistant spread measure.
1/f noise
Noise with more power at slow timescales.
Matched filter
Correlating data with a template of the expected signal.
Periodogram
Detection strength plotted against trial period.
Phase folding
Wrapping time modulo the period so all orbits overlap.
SNR / ppm / AU
Signal-to-noise ratio / parts per million / Earth–Sun distance.

7. Assumptions and Limitations

  1. Stellar mass and radius in File 6 are catalog inputs, not pipeline outputs.
  2. The orbit is assumed circular and the planet's mass negligible.
  3. √δ ignores limb darkening and assumes a central-ish crossing.
  4. The σ/√N gain assumes independent white noise, which is why detrending (File 3) must come first.
  5. Worked-example numbers use literature-style stellar parameters I supplied for illustration; your script's values depend on its inputs.
